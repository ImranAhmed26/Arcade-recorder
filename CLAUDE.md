# Arcade — Project Guide for Claude

Native macOS screen recorder (Loom-inspired MVP). SwiftUI + ScreenCaptureKit +
AVFoundation + FFmpeg. The repo is named `make my prompts better` locally /
`Arcade-recorder` on GitHub; the app is branded **Arcade** everywhere user-facing.

## Branching model

```
feature branch  →  PR into  dev  →  PR into  main
```

- **`main`** — production. Protected: PR-only, no direct/force push, no deletion.
- **`dev`** — default + integration branch. Feature work lands here first.

## How Claude works in this repo (standing rule)

When asked to implement a system/feature that warrants isolation:

1. **Branch off `dev`** with a descriptive name (`feat/…`, `fix/…`, `chore/…`).
   - Skip the branch for tiny, obvious edits — use judgment.
2. Implement, then **commit with a clear, descriptive message** (imperative
   subject + a body explaining what/why). End commit messages with:
   `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`
3. **Before pushing or opening the PR, sync with the latest `dev`**
   (`git fetch origin dev` then `git rebase origin/dev`, or merge). **Resolve any
   merge conflicts** and re-verify the build so the PR merges cleanly with no
   conflicts. If a rebase rewrote history on an already-pushed branch, push with
   `--force-with-lease`.
4. **Push** the branch and **open a PR with base `dev`**.
5. **Never open PRs into `main`.** The user promotes `dev → main` themselves.

## Phasing rule — protect the recording pipeline

Never bundle a large UI change with edits to the capture/session path in one step.
Split work into phases and keep all pipeline-touching changes in a final, minimal,
independently-revertable phase:

1. **UI-only** — design system, navigation, layouts, restyles. Must wire to the
   *existing* config/behavior and leave the recording engine byte-identical. Verify
   visually + record one clip to confirm output is unchanged.
2. **Config/state** — add new config fields + persistence + their controls, kept
   **inert** (not yet read by the recording session). Verify persistence + UI.
3. **Behavior integration** — the only phase that may affect capture: flip the
   session to read the new state. Keep the diff tiny and run the full recording
   regression (countdown variants, screen-only vs screen+camera, overlay capture-
   exclusion, merge/export output).

The capture engine (`ScreenRecorder` / `CameraRecorder` / `RecordingWriter`) should
stay untouched unless a change is genuinely about capture itself.

## Build / run

The Xcode project is generated by **XcodeGen** — after adding/removing files or
editing `project.yml`, regenerate before building:

```
xcodegen generate
xcodebuild -project Arcade.xcodeproj -scheme Arcade -configuration Debug -destination 'platform=macOS' build
```

Install + launch the built app:

```
cp -R ~/Library/Developer/Xcode/DerivedData/Arcade-*/Build/Products/Debug/Arcade.app /Applications/Arcade.app
open /Applications/Arcade.app
```

Signing: a local self-signed cert (`Arcade Local Dev`) for stable Screen
Recording TCC permission across rebuilds — no Apple Developer team.

## Architecture map

- `Arcade/Models/` — `AppState` (phase + auth wiring), `RecordingConfig`, `Recording`, `UserSession`.
- `Arcade/RecordingEngine/` — `ScreenRecorder` (SCStream), `CameraRecorder`, `RecordingWriter`.
- `Arcade/Utils/MergeService.swift` — FFmpeg compositing (circular webcam overlay, HEVC export).
- `Arcade/WindowManager/` — floating overlay `NSPanel`s (webcam circle, control bar).
- `Arcade/Auth/` — Google OAuth (PKCE + ASWebAuthenticationSession), Keychain, `AuthService`.
- `Arcade/Views/` — SwiftUI screens; `Arcade/DesignSystem/` — `Theme` + components.
